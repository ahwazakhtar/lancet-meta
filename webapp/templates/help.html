How the reviewer app works

End-to-end walkthrough with annotated screenshots. Jump straight to a topic via the index, or read top-to-bottom — it follows the natural review flow.

1. Sign in 2. Dashboard 3. Check out 4. Paper info 5. Tables 6. Outcomes 7. Timepoints 8. Estimates 9. Saving 10. Re-extract flag 11. Release vs Done 12. Dual review 13. Admin

1 · Sign in

Sign-in is email-only — no password. The first time you sign in with a new email, a reviewer account is created automatically. Your email is recorded against every edit you make for audit attribution.

2 · Dashboard

The dashboard at / lists every paper. Each row shows ID, title, year, intervention, effect-size count, the 2-reviewer progress, current checkout state, and an edit-status indicator.

The re-extract badge appears if either the paper itself is flagged or any of its estimates is flagged. Use the search bar and dropdowns to filter; click ↻ Refresh from Sheet (top right) to pull the latest Sheet contents into the local DB (checked-out papers are skipped).

3 · Check out

Clicking Check out locks the paper to you. Other reviewers see locked; admins can still view as read-only. You land on Paper info so you have the bibliographic context first.

4 · Paper info

Bibliographic and study-level metadata. Free-text fields render as inputs; enum-like fields (publication type, risk-of-bias judgment, setting type, etc.) render as dropdowns so you can't accidentally introduce variant spellings.

Three actions live at the bottom:

  • Save paper edits — persists every field on the page.
  • Flag for re-extraction (toggles to Unflag re-extract when set) — marks the paper for the next extraction pass.
  • Delete — soft-deletes the paper (hidden from list, excluded from publishes).

5 · Step 1 — Tables

The pipeline parses every table out of the paper's markdown and lists them here. For each table, choose Effect-size table, Not an effect-size table, or leave it undecided. Only tables flagged as effect-size flow into Steps 2-4.

The selected option is filled (dark); the other is outlined. You can't click Done until every table is classified — undecided tables block submission.

Use Add a table manually at the bottom only if the parser missed a real table — its outcomes / timepoints / estimates are added from scratch.

6 · Step 2 — Outcomes

For each effect-size table, list every outcome it reports. Each outcome has a short name, a domain (Mortality / Injury / Crime / etc.), and a definition.

7 · Step 3 — Timepoints

List the timepoints each effect-size table reports — e.g. baseline, endline, 12 mo, 1991-2016. A single overall window counts as one timepoint.

8 · Step 4 — Estimates

The actual numbers. Each estimate is one (table, outcome, timepoint) triple. Estimates carry the full 25-field schema: effect_size_raw, ci_or_se_raw, effect_value, lower_ci, upper_ci, etc. direction_of_effect renders as a dropdown (↓ beneficial / ↑ harmful / ↔ null / data not available).

Orphan estimates — at the bottom of the page you may see estimates not linked to any current table. These are usually leftovers from an earlier extraction. Re-link them via the dropdowns or delete them.

9 · Saving your work

Each row card has a Save button that persists just that row. For pages with many rows (Outcomes, Timepoints, Estimates), a sticky save bar sits at the top — click Save draft to fire every row's Save in one click.

Your draft persists across sign-outs as long as the paper stays checked out. If you close the browser and come back tomorrow, your edits are still there. The lock is only released when you click Release, Done, or an admin force-releases.

10 · Re-extract flag

Two places to flag rows that the LLM clearly got wrong and need to be re-processed:

  • Paper info — a Flag for re-extraction button next to Save flags the whole paper for the next extraction pass.
  • Estimate row — a Flag re-extract button on each estimate card flags just that estimate.

Both buttons toggle: clicking again on an already-flagged target unflags it. The dashboard re-extract badge appears if either the paper or any of its estimates is flagged, so a single bad estimate is visible from the top-level view.

11 · Release vs Done (important)

Both buttons release your lock. They differ in whether they record you as one of the 2 reviewers:

When to use You're finished reviewing this paper. You checked out by mistake, or you don't want to review this paper.

Only click Release if you're not going to work on this paper anymore. If you're just stepping away briefly, leave it checked out — your lock persists until you Release or Done.

12 · Dual review (max 2 reviewers per paper)

Each paper supports up to two distinct reviewers. The Reviews column on the dashboard shows the progress:

  • 0 / 2 — not yet reviewed.
  • 1 / 2 — one reviewer has clicked Done. Hover for the email.
  • 2 / 2 — fully reviewed. No new reviewers can check out the paper.

Review is sequential, not blind — the second reviewer sees the first reviewer's edits. After 2 / 2 is reached, only the two existing reviewers (and admins) can re-check-out to amend. A reviewer can re-check-out and click Done any number of times — only one slot is consumed.

13 · Admin actions

Admins (is_admin = True) get extra capabilities:

  • Force release — release someone else's checked-out paper. Available in the draft banner when viewing a held-by-another paper.
  • View as admin — read a draft someone else owns.
  • Publish to Sheet — overwrite the Google Sheet with the current local DB. From /admin.
  • User management — promote / remove reviewers from /admin.

Anyone (not just admins) can ↻ Refresh from Sheet on the dashboard — that pulls Sheet contents into the local DB and skips any paper currently checked out so in-progress drafts aren't trashed.
